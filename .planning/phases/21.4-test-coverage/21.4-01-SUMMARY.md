## Deviations from Plan

### Auto-selected pattern changes

**1. [Rule 2 – Pattern] Direct async function calls instead of ASGI transport for router tests**
- **Found during:** Task 1
- **Issue:** ASGI transport routes through FastAPI's dependency injection, which re-creates sessions. Direct function injection with `session=session` gives reliable coverage tracing.
- **Fix:** Used `await pair_send_link(req, session=session, settings=settings)` pattern throughout.
- **Files modified:** tests/test_auth_router_coverage.py

**2. [Rule 2 – Pattern] FakeServer class for OAuth callback coverage**
- **Found during:** Task 2
- **Issue:** The run_google_oauth_flow / run_slack_oauth_flow functions spin up an internal FastAPI app. To cover the callback route, a FakeServer class captures the app and invokes it via ASGITransport in a new event loop.
- **Fix:** FakeServer pattern in test_slack_oauth_coverage.py and test_microsoft_oauth_coverage.py (Slack success + error paths, Microsoft error/ValueError path).
- **Files modified:** tests/test_slack_oauth_coverage.py, tests/test_microsoft_oauth_coverage.py

**3. [Rule 1] pair_complete magic-link path has no-email guard (line 149-151)**
- **Found during:** Task 1
- **Issue:** The branch `if not pairing_email: raise HTTPException(400)` requires a PairingCode row with user_id=None and email=None. This is only reachable via direct DB manipulation – the pair_send_link endpoint always sets email. Not tested; not reachable via any normal flow.
- **Fix:** Documented in test file module docstring. Counted as unreachable-in-practice.
- **Files modified:** tests/test_auth_router_coverage.py (docstring only)

None of the above required user decision (Rule 4).
