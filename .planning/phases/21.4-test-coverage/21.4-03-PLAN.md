<objective>
The roadmap goal calls for an E2E smoke test covering "pairing → onboarding → voice connect happy path". Currently every backend test exercises one router in isolation. This plan adds ONE end-to-end test that walks the full new-user flow against the full FastAPI app, with external services mocked at their HTTP/SDK boundaries.

Purpose: Catch wiring regressions across routers (auth + integrations + users + livekit) that no individual unit test would.
Output: A new `tests/e2e/` package with one smoke test, marked `@pytest.mark.e2e`.

Note: A device-driven iOS E2E (XCUITest from launch through voice connect) is out of scope here — XCUITest against a live LiveKit room requires either device automation infra or a mocked LiveKit client SDK, both of which are bigger than this phase. We capture the equivalent path via the backend E2E test plus the iOS unit/integration tests in Plan 02.
</objective>

    1. **Send magic link**: POST /auth/pair/send-link {email: "newuser@test.com"} → 204. Assert `mock_resend` was called once with that email.
    2. **Extract pairing code**: query the test DB directly for the PairingCode row created for that email; pull the 6-digit code. (Or capture from mock_resend call args if the magic link includes it.)
    3. **Complete pairing**: POST /auth/pair/complete {code, device_name: "iPhone Test"} → 200. Assert response has access_token, refresh_token, expires_in.
    4. **Connect Google integration**: GET /integrations/google/connect (with Bearer access_token) → 200 with authorize_url. Then simulate the OAuth callback: GET /integrations/google/callback?code=fake&state=... → 200 (or 302). Assert IntegrationCredential row exists for that user with provider=google.
    5. **Set briefing schedule**: PUT /users/me/preferences {briefing_time: "07:30", timezone: "Australia/Brisbane"} → 200. Assert BriefingConfig row updated.
    6. **Read integration status**: GET /integrations/status → 200 with google.connected == true.
    7. **Issue LiveKit token**: POST /livekit/token (or whatever the endpoint is) with Bearer auth → 200 with `token` field present and JWT-shaped (`token.split('.') has 3 parts`).
    8. **Refresh access token**: POST /auth/token/refresh {refresh_token} → 200 with new access_token.

    Mark with `@pytest.mark.e2e`. No skips, no xfails. If any backend wiring is genuinely broken so this can't pass, FILE THAT AS A BUG (do not weaken the test) and update STATE.md blockers.
