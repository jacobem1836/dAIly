  <action>
    1. Check if a `Dockerfile` for the FastAPI app exists. If yes, mimic its base image, system deps, and uv install pattern. If no, create both following this pattern.

    2. Create `Dockerfile.worker`:
       ```dockerfile
       FROM python:3.11-slim

       # System deps for audio: ffmpeg + libsndfile for any audio-frame work the SDK does
       RUN apt-get update && apt-get install -y --no-install-recommends \
           ffmpeg libsndfile1 ca-certificates curl \
           && rm -rf /var/lib/apt/lists/*

       # Install uv
       RUN pip install --no-cache-dir uv

       WORKDIR /app

       # Install Python deps first (better layer caching)
       COPY pyproject.toml uv.lock* ./
       RUN uv sync --frozen --no-dev || uv sync --no-dev

       # Copy source
       COPY src ./src
       COPY alembic.ini ./
       COPY alembic ./alembic

       # Pre-download Silero VAD model so first dispatch isn't delayed
       RUN uv run python -m daily.worker download-files || true

       ENV PYTHONUNBUFFERED=1
       CMD ["uv", "run", "python", "-m", "daily.worker", "start"]
       ```
       Note: The `livekit-agents` CLI provides `download-files` for plugins (Silero etc.) and `start`/`dev` subcommands. Use `start` for prod and `dev` for the dev compose file.

    3. Update `docker-compose.yml` — append a `worker` service:
       ```yaml
         worker:
           build:
             context: .
             dockerfile: Dockerfile.worker
           command: ["uv", "run", "python", "-m", "daily.worker", "dev"]
           depends_on:
             - postgres
             - redis
             - livekit
           environment:
             LIVEKIT_URL: ws://livekit:7880
             LIVEKIT_API_KEY: devkey
             LIVEKIT_API_SECRET: secret
             DATABASE_URL: postgresql+asyncpg://daily:daily_dev@postgres:5432/daily
             DATABASE_URL_PSYCOPG: postgresql://daily:daily_dev@postgres:5432/daily
             REDIS_URL: redis://redis:6379/0
           env_file:
             - .env
           volumes:
             - ./src:/app/src  # live reload in dev
       ```
       The `env_file: .env` lets developer-local secrets (DEEPGRAM_API_KEY, CARTESIA_API_KEY, OPENAI_API_KEY) flow in without baking into the image.

    4. Update `docker-compose.prod.yml` — append a worker service mirroring the dev one but:
       - command: `["uv", "run", "python", "-m", "daily.worker", "start"]`
       - no source bind-mount
       - LIVEKIT_URL/API_KEY/API_SECRET pulled from `${LIVEKIT_URL}` etc. environment substitution (matching the existing prod compose pattern)
       - `restart: unless-stopped`
  </action>

  <how-to-verify>
    Pre-conditions:
    1. `.env` has valid `OPENAI_API_KEY`, `DEEPGRAM_API_KEY`, `CARTESIA_API_KEY`, `JWT_SECRET`, `VAULT_KEY`.
    2. A briefing has been pre-cached in Redis for user_id=1. Quickest path: run `daily chat` once via CLI to trigger the briefing pipeline, OR seed Redis manually with a fake narrative.
    3. iOS app (or Android app) `Config.backendBaseURL` is set to a tunnel URL (cloudflared/ngrok) pointing at `localhost:8000` running FastAPI on the host.

    Steps:
    1. `docker compose up -d` — full stack including worker.
    2. Run FastAPI on the host: `uv run uvicorn daily.main:app --reload --port 8000` (or add fastapi service to compose if already containerized).
    3. Start tunnel: `cloudflared tunnel --url http://localhost:8000`
    4. Pair the iPhone via the magic-link flow (Phase 19 mechanic). Confirm access JWT received.
    5. Tap to start a voice session in the iOS app. The app calls POST /livekit/token, receives a room JWT, joins room `session-1-{ts}`.
    6. Within ~3s, the iOS app's state should transition from `.connecting` → `.listening` → `.speaking` (agent is publishing TTS audio).
    7. **Listen.** You should hear the briefing narrative spoken via Cartesia voice through the iPhone speaker. (If silence, check `docker compose logs worker` for the briefing log line.)
    8. After the briefing finishes, say "What's the first email about?" or "Tell me more." The iPhone state should go `.speaking` → `.listening` → `.speaking` with a coherent response.
    9. Say "exit" or hang up — confirm the agent disconnects cleanly.
    10. Repeat steps 6–9 with the Android app for full coverage.

    Expected outcomes:
    - Briefing audio plays end-to-end on first connect.
    - Voice turns work (STT transcribes correctly, LLM responds in <3s, TTS plays back).
    - No `Traceback` / 5xx / disconnect errors in `docker compose logs worker` during the session.

    Failure modes to look for and document in the smoke test note:
    - Briefing silent → Redis cache miss (run briefing pipeline first) OR DailyAgentLLM not feeding tokens
    - Audio one-way (you hear briefing but mic doesn't reach agent) → Deepgram plugin misconfigured
    - Agent disconnects immediately → check `parse_user_id_from_room` logs; room name might not match pattern
  </how-to-verify>
