<objective>
Fix the `.env` / `.env.example` drift and add fail-fast startup validation. `.env` has 24 vars; `.env.example` documents only 10, so a fresh clone copying the example cannot boot and silently runs on insecure defaults (empty `vault_key`, `jwt_secret`, dev LiveKit creds). Worse, `config.py` gives every field a default (including secrets), so a missing required secret never errors — it just produces broken runtime behaviour later. This plan regenerates `.env.example` to document all 24 vars with placeholders, and makes truly-required vars fail fast at boot with one clear message listing everything missing.

Purpose: Boot reliability. Removes a class of silent misconfig that surfaces only deep in a voice/auth session.
Output: Complete `.env.example`; `config.py` raises a clear, aggregated error at startup when required secrets are absent.
</objective>
