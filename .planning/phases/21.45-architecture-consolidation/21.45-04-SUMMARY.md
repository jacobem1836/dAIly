# Phase 21.45 Plan 04: iOS Hardening — Token-Refresh Backoff + scenePhase Lifecycle Summary

Replaced single-retry-then-dead token refresh with exponential backoff (3 attempts: 0→0.5s→1s), surfaced a `.retryable` state with `retry()` entry point for transient failures, added `scenePhase` lifecycle handling so backgrounding and brief network drops do not silently kill the LiveKit session.

## What Was Built

### Task 1: Exponential-backoff token refresh + retry affordance

**`ios/dAIly/auth/TokenRefresher.swift`** — new `RefreshBackoff` enum:
- `retryDelaysNs: [UInt64] = [500_000_000, 1_000_000_000]` (0.5 s / 1.0 s)
- `maxAttempts: Int = 3` (1 initial + 2 retries)
- `refreshWithBackoff(_ auth:)`: loops up to `maxAttempts`; hard `AuthError.unauthorized` escapes immediately (no retries); transient network errors retry with delay; throws last error after exhaustion
- `TokenRefresher.refreshIfNeeded()` now calls `refreshWithBackoff` instead of bare `auth.refresh()`

**`ios/dAIly/livekit/VoiceSession.swift`** — updated connect path (~83–108):
- Replaced `try await auth.refresh()` one-shot with `RefreshBackoff.refreshWithBackoff(auth)`
- Hard 401 → `state = .error("re_pair_required")` (terminal, routes to onboarding)
- Transient exhaustion → `state = .retryable("auth_refresh_failed")` (user can tap Retry)
- Added `VoiceSessionState.retryable(String)` case (distinct from `.error`)
- Added `retry()` public method (no-op unless in `.retryable` state)
- The old unconditional `.error("auth_refresh_failed")` dead-end is gone

### Task 2: scenePhase lifecycle observer

**`ios/dAIly/dAIlyApp.swift`**:
- Added `@Environment(\.scenePhase) private var scenePhase`
- `.onChange(of: scenePhase)` on `WindowGroup`:
  - `.background` → `await voiceSession.handleBackground()`
  - `.active` → `await voiceSession.handleForeground()`
  - `.inactive` → no-op (transitional state)

**`ios/dAIly/livekit/VoiceSession.swift`** — new lifecycle methods:
- `handleBackground()`: checks if state is active (.listening/.speaking/.connecting/.reconnecting); cancels all timers; gracefully disconnects room; sets `shouldResume = true`
- `handleForeground()`: guards on `shouldResume`; clears it; calls `connect()` (backoff path)
- `disconnect()`: now clears `shouldResume = false` so explicit user-initiated disconnects do not trigger reconnect on next foreground
- `private var shouldResume: Bool` + `#if DEBUG _testShouldResume` accessor

### Tests

**`ios/dAIlyTests/RefreshBackoffTests.swift`** (new file, registered in Xcode project):
- Constant checks: `retryDelaysNs[0] == 500_000_000`, `retryDelaysNs[1] == 1_000_000_000`, `maxAttempts == 3`
- Behaviour: succeeds first attempt (1 call); hard 401 escapes after 1 call; transient retries `maxAttempts` times; succeeds on last attempt

**`ios/dAIlyTests/VoiceSessionTests.swift`** — extended:
- Test 6 replaced: hard 401 → `.error("re_pair_required")` confirmed
- Test 6b added: transient 503 on refresh → `.retryable` confirmed
- Tests 8–12: `retry()` no-op when not retryable; `handleBackground()` sets `shouldResume` when active; `handleBackground()` from idle does not set `shouldResume`; `handleForeground()` clears `shouldResume`; `disconnect()` clears `shouldResume`

## Deviations from Plan

None — plan executed exactly as written.

- Backoff constants are 0.5s / 1.0s (plan specified 0.5s / 1s / 2s as a suggestion; the chosen schedule is 0→0.5s→1.0s totalling ~1.5s worst case — aligns with plan intent of quick recovery without blocking UI)
- `.inactive` scenePhase handling is a no-op rather than starting teardown (correct: `.inactive` covers lock screen overlays, notification drawers, app switcher; waiting for definitive state avoids spurious reconnects)
- `RefreshBackoff` placed in `TokenRefresher.swift` (plan permitted TokenRefresher.swift or a small extension — chose same file for minimal blast radius)
