## Accomplishments

- `.env.example` now documents all 24 vars from `.env`, grouped by concern (Database, Cache, Security, LLM, STT/TTS, LiveKit, OAuth, Email, Mobile, Briefing, Logging), with `# REQUIRED` annotations on the 6 vars that must be set for the app to boot
- `Settings.model_validator(mode="after")` collects every empty required var and raises one `ValueError` naming all of them in UPPER_SNAKE form and pointing at `.env.example` — startup now fails clearly rather than silently operating with empty secrets
- Added `log_level: str = "INFO"` field so `LOG_LEVEL` is documented on the Settings model (was previously ignored via `extra="ignore"`, undiscoverable)
- 9 new config validation tests verify the aggregated error, env-file isolation, and the optional-var safety net

## Decisions Made

- **LOG_LEVEL**: Added as `log_level: str = "INFO"` on Settings rather than leaving as undocumented runtime-only var
- **Required var set**: `vault_key, jwt_secret, openai_api_key, deepgram_api_key, cartesia_api_key, resend_api_key`. Integration OAuth creds (Google, Slack, Microsoft) are per-provider optional — excluded. DB/Redis/LiveKit have working local-dev defaults — excluded.
- **Validation approach**: `model_validator(mode="after")` on the Settings class. Reads from the already-constructed instance so tests can inject values via keyword args without monkey-patching.
- **Test isolation pattern**: Tests that construct Settings directly must pass `_env_file=None` (prevents loading the developer's real `.env`) and all 6 required fake values.
