# Phase 21.45: Architecture Consolidation - Context

**Gathered:** 2026-06-19
**Status:** Ready for planning
**Source:** Integration-friction review (Option A) — `.planning/reviews/2026-06-19-integration-friction-review.md`

<domain>
## Phase Boundary

This phase retires the half-finished voice migration and removes duplicated / premature surface BEFORE Phase 21.5 (Adaptive Learning) is built on top of it. It is **Option A** (minimal-risk evolution) from the 2026-06-19 review: **no infrastructure change** (LiveKit stays self-hosted, coturn stays, api+worker stay split). It deletes duplicated *implementations*, adds the one missing test, fixes config drift, hardens iOS for real mobile conditions, and records two scope decisions. **No user-facing feature is removed.**

Root problem being fixed: two parallel voice architectures exist. `src/daily/voice/` (1,316 LOC local CLI mic→Deepgram→graph→Cartesia→speaker pipeline) duplicates `src/daily/worker/voice_pipeline.py` (delegates the identical pipeline to the `livekit-agents` library, the production mobile path). They use different checkpointers (`MemorySaver` in CLI vs `AsyncPostgresSaver` in worker). This doubles the blast radius of every voice change and is why recent work is live-session whack-a-mole. STATE.md carried an unresolved decision ("keep Python voice loop alive or stub it") — **resolved 2026-06-19: delete it.**
</domain>

<decisions>
## Implementation Decisions (locked)

### Voice path consolidation (workstream 1)
- DELETE `src/daily/voice/` entirely (`stt.py`, `tts.py`, `loop.py`, `barge_in.py`, `utils.py`, `__init__.py` — ~1,316 LOC).
- DELETE the `voice` command in `src/daily/cli.py` (caller at ~cli.py:789-790 `run_voice_session`). Remove the legacy `_run_chat_session` text path only if it depends on `voice/`; if it depends solely on the orchestrator graph, it may remain as a thin dev harness.
- The single production voice path is `worker/` → `livekit-agents` `VoicePipelineAgent` (Deepgram STT + Cartesia TTS + barge-in handled by the library). No hand-rolled STT/TTS/barge-in remains.
- Collapse the dual checkpointer to `AsyncPostgresSaver` only. Remove the `MemorySaver` path. If the CLI dev harness still needs an ephemeral run, it uses `AsyncPostgresSaver` against the dev DB (or is dropped).
- **GATE (do this first, before any deletion):** prove nothing in the production flow imports `voice/`. Run `grep -rn "daily.voice\|from .voice\|import voice" src/daily/main.py src/daily/worker/ src/daily/livekit/ src/daily/orchestrator/`. Expected: only `cli.py` references `voice/`. If anything else references it, STOP and surface it.

### E2E smoke test (workstream 2)
- Add ONE backend E2E smoke test for the production voice path: pair (`/auth/pair`) → `/livekit/token` → LiveKit room join → worker agent greeting delivered → one approval-interrupt round-trip (draft → approval `interrupt()` → resume confirm).
- Phase 21.4-03 already added a `pairing → onboarding → voice connect` backend smoke (`tests/.../test_*smoke*`). EXTEND that test to assert the agent greeting + approval round-trip rather than creating a duplicate file. LiveKit/worker externalities may be faked (fakeredis is already a dev dep; mock the LiveKit room + livekit-agents pipeline at the boundary). The test must exercise the orchestrator approval interrupt with a real graph, not a mock graph.
- Test must run in CI (pytest) and fail if the approval round-trip or greeting path breaks.

### Config drift fix (workstream 3)
- Regenerate `.env.example` to document ALL 25 vars currently in `.env` (currently only 10). The 15 missing include: `DATABASE_URL_PSYCOPG`, `OPENAI_API_KEY`, `DEEPGRAM_API_KEY`, `CARTESIA_API_KEY`, `REDIS_URL`, `LOG_LEVEL`, `BRIEFING_EMAIL_TOP_N`, `BRIEFING_SCHEDULE_TIME`, `LIVEKIT_URL`, `LIVEKIT_API_SECRET`, `LIVEKIT_API_KEY`, `JWT_SECRET`, `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, `MAGIC_LINK_BASE_URL`. Use placeholder/example values, never real secrets.
- Add fail-fast startup validation: required vars without a safe default must raise a clear error at boot (pydantic-settings in `src/daily/config.py` — make required fields have no default; or add a startup check that lists all missing required vars at once). A fresh clone copying `.env.example` and filling values must boot.

### iOS hardening (workstream 4)
- Token refresh: replace the single-retry-then-unrecoverable logic (`ios/dAIly/auth/AuthService.swift` ~67-82, `ios/dAIly/livekit/VoiceSession.swift` ~71-89) with exponential backoff (e.g. 3 attempts, 0.5s/1s/2s) and a user-facing retry affordance on terminal failure instead of a dead `.error` state.
- Add a `scenePhase` lifecycle observer (in `dAIlyApp.swift` or `VoiceSession`) so app backgrounding and brief network drops trigger graceful pause/reconnect rather than a silently dropped LiveKit session. On return to `.active`, attempt reconnect if a session was live.
- iOS-only changes; Android is frozen (see decisions below). Mirror to Android later (out of scope here).

### Scope decisions to record (workstream 5)
- FREEZE Android development. iOS is the only TestFlight target for this milestone. Record in ROADMAP (Phase 20 / v2.1 note) and STATE.md. Android voice plumbing exists but onboarding/integration/permissions UI is absent; do not maintain parity now.
- DELETE the iCloud sync-conflict duplicate files. Dry-run list first: `find . -name '* 2.*' -not -path './.git/*' -not -path './.venv/*'`. Then delete (`-delete`). Verify zero remain. Also move/keep the repo off the iCloud-synced path is NOT in scope (note it as a follow-up).

### Claude's Discretion
- Exact test mocking boundary for LiveKit/livekit-agents in the smoke test.
- Backoff constants and retry-UI copy on iOS.
- Whether the CLI keeps a minimal text-only dev harness or is removed entirely (decide from the import-gate result).
</decisions>
