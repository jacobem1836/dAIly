## Decisions Made

**Mock boundary for LiveKit/livekit-agents:** `DailyLLMBridge` is tested directly, bypassing `VoicePipelineAgent`, `ChatContext`, and any LiveKit room plumbing entirely. This is the exact seam between the transport layer and the orchestrator — exercising it proves the voice→graph path works without needing a real WebRTC connection.

**OpenAI mock strategy:** `astream_session` in `session.py` uses `_get_openai_client()` (module-level cached client) and calls `create()` with `stream=True`, which must return an async generator. A `_smart_create` coroutine dispatches on the `stream` kwarg: when `True`, it returns an async generator yielding fake chunks; when `False` (respond_node / draft_node), it returns the current `_current_response` attribute on the mock client. This lets the test switch between respond-format and draft-format responses between turns by setting `mock_llm_client._current_response`.

**Greeting turn message:** "Good morning, brief me" is used (not "what is on my schedule?"). The word "schedule" is a draft keyword in `route_intent` which would route the first turn to `draft_node` instead of `respond_node`. The test must use a genuinely respond-intent message for the greeting step.

**CI e2e marker:** The e2e tests use `@pytest.mark.e2e`. The default `pyproject.toml` pytest configuration has `addopts = "-m 'not e2e'"` which EXCLUDES e2e tests from normal CI runs. The smoke tests must be opted into explicitly with `-m e2e` or by removing the exclusion for a full E2E CI job. This is documented here but not changed (changing CI configuration was out of scope for this plan).

- **Found during:** Task 1 (RED phase run)

**2. [Rule 1 - Bug] astream_session streaming mock required async generator dispatch**
- **Found during:** Task 1 (RED phase run)
- **Issue:** Patching `AsyncOpenAI` class and setting `.chat.completions.create = AsyncMock(return_value=...)` does not work for `astream_session` because it iterates `async for chunk in stream:` — the create() call must return an async iterable, not a `MagicMock`. The module-level `_openai_client` is also a separate code path from the `AsyncOpenAI(api_key=...)` constructor called in nodes.
- **Fix:** Created a `_smart_create` async function that returns an async generator when `stream=True` (for `astream_session`), and returns `mock_llm_client._current_response` when `stream=False` (for graph nodes). Patched both `daily.orchestrator.nodes.AsyncOpenAI` (constructor mock) and `daily.orchestrator.session._openai_client` (module-level cached client) via `patch.object`.
- **Files modified:** `tests/e2e/test_smoke_pairing_to_voice.py`
- **Committed in:** `c270462` (task commit)
