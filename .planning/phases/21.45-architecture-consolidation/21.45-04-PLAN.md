<objective>
Harden the iOS client for real mobile conditions. Today token refresh is single-retry-then-dead: one 401 → one `auth.refresh()` → second failure → unrecoverable `.error("auth_refresh_failed")` with no backoff and no user retry affordance (`VoiceSession.swift:71-89`, `AuthService.swift` refresh path). There is also no `scenePhase` observer, so backgrounding the app or a brief network drop can silently drop the LiveKit session. This plan replaces the single-retry logic with exponential backoff (3 attempts: 0.5s / 1s / 2s), surfaces a user-facing retry affordance on terminal failure, and adds a `scenePhase` observer that gracefully pauses on background and reconnects on return to `.active` when a session was live.

Purpose: Mobile stability — the network-churn and lifecycle edge cases that only appear on real devices. iOS-only; Android is frozen (Plan 03) and not mirrored here.
Output: Backoff-based refresh with retry UI; scenePhase-driven pause/reconnect in the iOS app.
</objective>
