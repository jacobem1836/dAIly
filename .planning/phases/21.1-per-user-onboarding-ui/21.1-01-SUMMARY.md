# Phase 21.1 Plan 01: State and Model Layer for Onboarding Summary

**One-liner:** AppState+Keychain onboarding flag, IntegrationProvider/State models, and OAuthCallbackParser with hasSuffix path matching — 18 new tests all green.

## What Was Built

Three tasks implementing the state and model layer that Plans 02-04 depend on:

1. **AppState.hasCompletedOnboarding** — new `@Published var hasCompletedOnboarding: Bool` initialized from Keychain key `onboarding_complete`. Follows the existing `hasAccessToken` init pattern exactly. Drives root routing in plan 04.

2. **IntegrationProvider enum + IntegrationState model** — `IntegrationProvider` is a `CaseIterable` enum with `google`, `microsoft`, `slack` raw values plus `displayName`, `description`, and `icon` metadata. `IntegrationState` is an `ObservableObject` with a `Set<String> connectedProviders`, `atLeastOneConnected` computed property, `markConnected(provider:)`, and `isConnected(_:)`. Designed to be lifted as `@StateObject` in plan 04.

3. **OAuthCallbackParser** — mirrors `PairCodeURLParser` pattern using `hasSuffix("/oauth/success")` instead of exact path match. Returns `provider` query parameter, nil on wrong path/missing query/empty value. Intentionally passes through unknown providers (caller validates per T-21.1-01-01).
