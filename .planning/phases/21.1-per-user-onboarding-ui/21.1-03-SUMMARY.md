# Phase 21.1 Plan 03: Onboarding Leaf Views Summary

**One-liner:** WelcomeView, IntegrationView (provider-parameterised with D-12 Skip gate and deep-link reactive state), ScheduleView (POSIX HH:mm + Keychain-after-backend), and CompletionView — all 4 build on iOS 16 with xcodebuild green.

## What Was Built

Three tasks implementing the four SwiftUI leaf views consumed by the OnboardingView TabView (plan 04):

### Task 1: WelcomeView + ScheduleView (commit f035179)

**WelcomeView** — tab 0 branded entry point. Single `onContinue: () -> Void` callback. Displays `"dAIly"`, `"Your AI daily briefing, every morning."`, and `"Get started"` CTA. No state — purely presentation.

**ScheduleView** — tab 5 briefing time picker. Defaults to 7:00 AM via `Calendar.current.date(bySettingHour: 7, minute: 0, second: 0, of: Date())`. On save: formats time with `DateFormatter` using `Locale(identifier: "en_US_POSIX")` and `dateFormat = "HH:mm"` (T-21.1-03-04 mitigation), calls `auth.savePreferences(briefingTime:timezone:)` with `TimeZone.current.identifier`, and only writes `KeychainStore.shared.save(key: "onboarding_complete", value: "true")` inside the success path of the `do` block — guaranteeing T-21.1-03-01 (Keychain flag never set if backend save fails).

### Task 2: IntegrationView (commit f19fb4f)

**IntegrationView** — single parameterised view for Google, Microsoft, and Slack tabs (D-09). Props: `provider: IntegrationProvider`, `auth: AuthService`, `@ObservedObject var integrationState: IntegrationState`, `isLastIntegrationPage: Bool`, `onContinue: () -> Void`.

- D-11: when `integrationState.isConnected(provider)` is true, the Connect button is replaced with a green checkmark + Continue button.
- D-12: `canSkip = !isLastIntegrationPage || integrationState.atLeastOneConnected` — Skip hidden on Slack page until at least one provider connected.
- D-13: Connect taps `auth.getIntegrationConnectURL(provider: provider.rawValue)` then `try auth.openOAuthSession(url: authURL)` (fire-and-forget, not async).
- Pitfall 4: `isConnecting` is cleared via `.onChange(of: integrationState.connectedProviders)` when the deep link arrives, not when the session callback fires.
- T-21.1-03-02: error messages are generic ("Connection failed. Please try again.") — no server error details surfaced.
- T-21.1-03-03: Connect button is `disabled(isConnecting)` — prevents multiple simultaneous sessions.

### Task 3: CompletionView (commit 65378f6)

**CompletionView** — tab 6 confirmation screen. Shows `"You're all set"` heading, briefing time formatted with `DateFormatter.timeStyle = .short`, connected provider list via `IntegrationProvider.allCases.filter { integrationState.isConnected($0) }.map(\.displayName)` (stable sort order via enum declaration), and `"Start talking to dAIly"` CTA calling `onFinish`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Used iOS 16-compatible .onChange signature**
- **Found during:** Task 2 build verification
- **Issue:** Plan spec included `.onChange(of:) { _, newValue in }` (two-argument closure) which is only available in iOS 17+. The project deployment target is iOS 16.0.
- **Fix:** Changed to single-argument `.onChange(of: integrationState.connectedProviders) { newValue in }` which is available from iOS 14+.

- **Commit:** f19fb4f (incorporated into same commit)
