## Navigation Architecture

| Option | Description | Selected |

## Onboarding State Persistence

| Option | Description | Selected |
|--------|-------------|----------|
| Keychain flag `onboarding_complete` | Fast, offline-capable, written at end of schedule setup | ✓ |
| Backend check on launch | Always accurate, requires network, handles multi-device | deferred |
| Derive from Keychain tokens | Equivalent to option A | — |

**User's choice:** A (Keychain flag), with network sync deferred
**Notes:** Jacob asked about the benefit of B over A. Explained that B catches state divergence (new device, forced re-onboarding, account issues) but the production pattern is both: local flag for fast render, network check to validate. Agreed the Keychain flag alone is sufficient for Phase 21.1.
