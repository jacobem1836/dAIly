<decisions>
## Implementation Decisions

### Bug Inventory

All bugs are in scope. Ordered roughly by severity:

- **D-01 (CRITICAL) LiveKit connect_failed** — App shows `connect_failed: Error Domain=io.livekit.s...` on the voice screen. Worker may not be running or `livekit_url` env var is misconfigured / unreachable from device. Fix: diagnose root cause (worker process not started vs URL mismatch), add clear error messaging. The existing 60-second agent-join timeout should surface a human-readable error — confirm it does.

- **D-02 (HIGH) Magic link doesn't open app** — Tapping the email link does not open the iOS app. The `onOpenURL` handler exists and works when called, but Universal Links are not routing to the app. Likely cause: AASA (`/.well-known/apple-app-site-association`) not being served correctly for the current tunnel URL, or `APPLE_TEAM_ID` is not set in `.env` so the AASA has a malformed `appID`. Fix: populate `APPLE_TEAM_ID` in env, verify AASA response, verify entitlements bundle ID matches.

- **D-03 (HIGH) Slack and Microsoft integrations do nothing** — OAuth connect flows exist for both providers (backend routes are implemented in `integrations/router.py`). The bug is that after connecting, the briefing pipeline does not actually fetch Slack or Microsoft data for the user's briefing. Fix: verify `IntegrationToken` records are saved for these providers post-OAuth, then ensure the briefing pipeline's context builder loads tokens for all connected providers (not just Google). The adapters exist — confirm they are invoked.

- **D-04 (HIGH) Briefing not triggered on first sign-in** — After a new user completes onboarding, no briefing is created. They connect integrations, hit the voice screen, and the agent either has no briefing or says "I don't have a briefing cached yet." Fix: add a backend endpoint `POST /briefings/trigger` that kicks off `run_briefing_pipeline` for the authenticated user. iOS calls this after `onboarding_complete` is written to Keychain (at the end of onboarding). Show a progress indicator in the CompletionView or the VoiceView waiting state while the briefing generates (can take 15–30s). No polling needed — a reasonable fixed loading screen or spinner is sufficient for v1.

- **D-05 (MEDIUM) Keypad doesn't dismiss after OTP entry** — After the user enters a 6-digit code in the OTP field, the numeric keypad stays on screen (visible behind the next slide — see screenshots). Fix: dismiss the keyboard (`UIApplication.shared.sendAction(#selector(UIResponder.resignFirstResponder), to: nil, from: nil, for: nil)` or SwiftUI `.focused` binding) when the 6th digit is entered (i.e. when `otpCode.count == 6`).

- **D-06 (MEDIUM) Google "app not verified" warning** — Google OAuth shows an "unverified app" interstitial for users who aren't added as test users. Fix for dev/TestFlight: add all test users as OAuth test users in the Google Cloud Console. Fix for production: this requires submitting for Google verification — note this as a production prerequisite, not a code fix. For now, document it as a known limitation and add test users manually.

- **D-07 (MEDIUM) Page indicator dots overlap content** — On the welcome screen (slide 1), the TabView page indicator dots overlap the "Get started" button (visible in screenshot). Fix: push the CTA button above the page dot area, or use `.safeAreaInset(edge: .bottom)` / explicit `padding(.bottom)` so the content never sits behind the dots.

- **D-08 (LOW) "magic link" → "link" copy** — All user-facing strings that say "magic link" should say "link". Two locations in `PairingView.swift`: the button label ("Send magic link" → "Send link") and the confirmation text ("We sent a magic link to..." → "We sent a link to..."). Comments in source can keep "magic link" as internal terminology.

- **D-09 (LOW) Add permissions step in onboarding** — A microphone permission request step should be added to the onboarding TabView before the voice screen is reached. `NSMicrophoneUsageDescription` is already in `Info.plist`. The step should call `AVAudioApplication.requestRecordPermission` and only advance if granted (or show a message explaining why it's required). Optionally request notification permission here too.

### Claude's Discretion

- Whether to use a spinner, progress bar, or animated indicator for briefing generation.
- Error message wording for the LiveKit connect_failed case.
- Sequencing/grouping of fixes into plans (planner decides).

</decisions>

- `run_briefing_pipeline` in `briefing/pipeline.py` — already exists, needs a thin HTTP endpoint wrapper
- `IntegrationToken` model — tokens are saved for all providers after OAuth; confirm context builder reads all of them

### Integration Points
- New `POST /briefings/trigger` endpoint → calls `run_briefing_pipeline(user_id=...)` → iOS calls at end of onboarding
- Permissions step → insert as a new TabView page in `OnboardingView`, before or after integrations

- Page indicator fix: the dots overlap the "Get started" button on the welcome slide (confirmed by screenshot). The fix should apply to all slides, not just welcome.
- Google "not verified": add test users to Google Cloud Console as the immediate fix. Document that production requires Google verification before public launch (this is a launch blocker, not a code bug).

</specifics>
